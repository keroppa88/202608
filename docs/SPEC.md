- 版: draft-1
- 作成: 2026-08-10
- 状態: **仮**。日本関連ソース（東証・日経・JPX API）の調査が未着手のため確定ではない。

---

## 1. 目的

海外の主要株価指数・セクター指数・REIT指数・商品指数・為替・個別銘柄、および日本の
主要指数・銘柄について、**日次の四本値（始値・高値・安値・終値）を継続的に記録する**。

### 背景にある要件

当初はスプレッドシート上で `GOOGLEFINANCE` 関数を並べる方式を検討したが、以下の理由で採らない。

- 銘柄数が増えるほど再計算が重くなり、全体が一括で失敗する
- 取得に失敗しても**エラーにならず空欄になる**ため、更新不全に気づけない
- 成否の記録・再試行・通知ができない

したがって本仕様は **「1銘柄 = 1リクエスト、成否を個別に記録する」** ことを中核に置く。

---

## 2. 設計方針

### 2.1 生データを無加工で保存し、抽出は後段で行う

取得したレスポンスは**一切加工せずそのままファイルに保存**する。四本値の抽出は
保存済みファイルを入力とする別処理として実装する。

理由:

- 抽出ロジックを変更しても、**再取得なしで過去分をやり直せる**
- 配信側のフォーマットが変わっても生データが残るため、原因を追跡できる
- 「取得失敗」と「抽出失敗」を別々の事象として扱える

### 2.2 XPath・CSSセレクタによる位置指定を使わない

HTML構造への依存は、相手のサイト改修で即座に破綻する。ページ全体を保存し、
後段で内容から抽出する方式とする。

### 2.3 銘柄ごとに独立して取得する

1銘柄の失敗が他の銘柄に波及しない構造とする。取得は銘柄単位でリトライし、
失敗した銘柄のみをエラーとして記録する。

### 2.4 「成功したように見える失敗」を必ず検知する

HTTP 200 が返っても中身が正しいとは限らない。以下を必須チェックとする。

| チェック | 内容 |
|---|---|
| 値の型 | 価格が数値であること（null・空文字を弾く） |
| 鮮度 | 取引所側タイムスタンプが一定日数以内であること |
| 銘柄同一性 | 配信元が返す銘柄名が期待と一致すること |

**§9 の検証記録に、実際にこの罠へ落ちた事例を残してある。**

## 3. データソース

### 3.1 採用（検証済み）

#### Yahoo Finance chart API

```
https://query1.finance.yahoo.com/v8/finance/chart/{symbol}?interval=1d&range=5d
```

- 認証不要。1リクエスト = 1銘柄
- レスポンスは JSON。`indicators.quote[0]` に四本値、`meta` に通貨・取引所・タイムスタンプ
- `meta.exchangeName` に配信元取引所コードが入る（`SNP` = S&P Dow Jones、`GER` = XETRA 等）
- **非公式API**。予告なく仕様変更・停止の可能性がある

#### MOEX ISS API（ロシアRTS）

```
現在値: https://iss.moex.com/iss/engines/stock/markets/index/securities/RTSI.json
履歴:   https://iss.moex.com/iss/history/engines/stock/markets/index/securities/RTSI.json?from=YYYY-MM-DD
```

- モスクワ取引所の公式データサービス。認証不要。ドキュメントは `https://iss.moex.com/iss/reference/`
- **履歴を期間指定で一括取得できる**ため、取得漏れを後から遡って復旧できる
- 注意: `iss.moex.com/robots.txt` は `Disallow: /`（§10 参照）

| ソース | 不採用の理由 |

## 5. ディレクトリ構成（案）

```
.
├── .github/workflows/
│   └── fetch.yml              日次 cron で起動
├── symbols.csv                銘柄マスタ
├── src/
│   ├── fetch.py               取得。生レスポンスを data/raw/ へ保存
│   └── extract.py             data/raw/ を入力に四本値を抽出し CSV 出力
├── data/
│   ├── raw/YYYY-MM-DD/        生レスポンス（無加工）
│   │   ├── yahoo_TSLA.json
│   │   └── moex_RTSI.json
│   ├── YYYY-MM.csv            月別の四本値
│   └── latest.csv             最新スナップショット
└── docs/
    └── SPEC.md                本書
```

Python は標準ライブラリのみを使用し、依存パッケージを持たない。

## 6. 出力形式

`data/YYYY-MM.csv` の列定義。

| 列 | 内容 |
|---|---|
| `fetched_at` | 取得実行時刻（UTC, ISO8601） |
| `category` | 分類（海外指数 / セクター / REIT / 商品 / 為替 / 個別株 …） |
| `name` | 表示名 |
| `symbol` | シンボル |
| `source` | データソース（`yahoo` / `moex` …） |
| `trade_date` | 取引日（配信元のタイムスタンプ由来） |
| `open` / `high` / `low` / `close` | 四本値 |
| `volume` | 出来高。**指数は 0 または空が正常** |
| `currency` | 通貨 |
| `exchange` | 配信元取引所コード |

### 注意

- **取引日は銘柄ごとに異なる。** 欧州・アジアは当日、米国は前営業日になることが常態。
  日付列を必ず参照すること
- 出来高 0 を異常値として弾かないこと（指数では正常）

## 7. 失敗検知

| 事象 | 検知方法 | 動作 |
|---|---|---|
| HTTP エラー | ステータスコード | 指数バックオフで最大3回リトライ |
| 価格が null / 非数値 | 型チェック | 当該銘柄をエラーとして記録 |
| 時系列が空 | `timestamp` の有無 | 配信停止の疑いとして記録 |
| 値が古い | 取引所タイムスタンプと現在日時の差 | 閾値超過でエラー |
| 銘柄の取り違え | `longName` と期待名の突合 | 初回登録時および定期的に目視確認 |

エラーが1件でもあればワークフローを **fail** させ、GitHub の通知経路で気づけるようにする。

**日次コミットの有無そのものが実行の証跡になる。**
コミットが無い日＝処理が走らなかった日、と判断できる。

## 10. ライセンス・公開に関する留意事項

本リポジトリは**公開**である。以下は認識した上で運用する。

- Yahoo Finance は非公式APIであり、利用が明示的に許諾されているわけではない
- `iss.moex.com/robots.txt` は `Disallow: /`。ただし MOEX 自身が
  ISS を公開ドキュメント付きのデータサービスとして提供している
- 株価指数の指数値は本来ライセンス商品であり、再配布には制約があり得る

### JPX API（有料）について — 要確認

**契約済みの有料データを公開リポジトリにコミットする場合、再配布にあたる可能性がある。**
利用規約を確認し、必要であれば以下のいずれかを採る。

1. 当該データのみリポジトリにコミットせず、Actions の Artifacts に保存する
2. リポジトリを非公開に変更する
3. 契約上問題ないことを確認した上でコミットする

認証情報は必ず **GitHub Secrets** に格納し、コードやログに出力しない。
